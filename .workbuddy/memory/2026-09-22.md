## 调研 JEV 系 BS 架构系统测试方案（三仓库源码级核验）

**交付物**：`20260922-jev-bs-e2e-research/`（README.md + final/report.md）

**调研对象与结论**
- `perixtar/jev-e2e`（TypeScript / **MIT** / 4★）：唯一端到端成品。用例 → 规划 → JEV 决策 → Playwright 执行 → 三态判定 → HTML+JSON+遮罩截图报告。**推荐作为自研骨架**。
- `CorieW/JevTest`（TypeScript / **无许可证，禁止依赖** / 0★）：进阶原型。四态判定 + 有界 BFS 状态图发现 + `issues[].source` 三分类 + 六项逐步回放校验。
- `browser-use/jev-ultrafast`（Python / MIT / **16,524★**）：执行引擎与决策协议参考，**不产出测试报告**。

**核心技术事实（供后续复用）**
- jev-e2e 用例格式：`Case:/Goal:/Input:/Auth:/Step:/Expect:`，`Expect` 为 **7 种封闭模板**（count/visible/absent/value/checked/url/number），`after reload` 后缀自动补 reload 步骤。
- 两道拒跑闸门：①无断言拒跑（"运行器不发明正确性标准"）②凭据字面量拒跑，强制 `@fixture`。
- 三态：PASS/FAIL/**BLOCKED**，聚合优先级 BLOCKED > FAIL > PASS；退出码 0/1/2/130。
- 可复现机制：控件 `fingerprint = [tag,type,role,label,context]` 存进 `plan.json`，回放零模型调用（0.977s vs 发现 1.832s）。
- planner 启用时做 **8 项防篡改校验**，含"负向测试意图不得被改成正向"。
- 性能：planner on 比 off 贵 5.5 倍、慢 2.5 倍。真实站点 eBay 每模型 3 次仅 1~2 次 PASS（受控 demo 的 200/200 不可外推）。

**三仓库共同的未解问题**：后端数据库隔离、测试数据重置归属、真实站点期望值管理。

**踩坑记录**
- GitHub **匿名 REST API 从本机 IP 出发 403 限流**（`api.github.com/rate_limit` core remaining=0）。改用 `gh`（在 `/opt/homebrew/bin/gh`，不在默认 PATH，需 `export PATH=/opt/homebrew/bin:$PATH`）；或直接 `git clone --depth 1` 读源码。
- 三仓库均极新（2026-09-16~18 创建），迭代快，引用数据前必须复核。

## 追加：page-agent 调研 + CDP 复用实测（第二轮，承接「基于谁叠加 E2E」）

**交付物**：`20260922-jev-bs-e2e-research/final/implementation-plan.md` + `scripts/`（两个可复跑实测脚本）

**新调研对象**
- `alibaba/page-agent`：TypeScript / **MIT** / **29,156★** / 2,618 fork / 推送至 2026-09-21 / Chrome 商店在架。**in-page JS agent**（页面内注入），`packages/{core,page-controller,extension,mcp,llms,ui}`。
- 官方定位声明：*"designed for **client-side web enhancement**, not server-side automation"*；DOM 与 prompt 派生自 browser-use。

**关键架构事实（源码级）**
- page-agent 的 `PageController` 是纯 DOM 层、跑在页面内；9 个工具：`done/wait/ask_user/click_element_by_index/input_text/select_dropdown_option/scroll/scroll_horizontally/execute_javascript`。**无 goto、无截图**。
- **判定是模型自述**：`done(text, success)` → `ExecutionResult.success`。`execute_javascript` 默认关闭（构造函数 `tools.delete`），官方警告会绕过安全与脱敏。
- **动作走 JS 合成事件**（`dispatchEvent`，`isTrusted=false`）：点击手动派发 pointerover/pointerenter/mouseover/pointerdown…；填值用 `getNativeValueSetter`。明确不支持 Monaco/CodeMirror/Draft.js。
- `patches/react.ts` 不是补 value setter，而是把 React 根容器标 `data-page-agent-not-interactive` 以排除误报。
- 扩展层才有导航与多页：`tabTools` 的 `open_new_tab/switch_to_tab/close_tab` 经 `customTools` 注入；`history-export.ts` 只是 history 的 JSON dump（无断言无判定）。
- 富扩展点（做测试臂有价值）：`customTools`（可覆盖/删除内置工具）、`onBeforeStep/onAfterStep/onBeforeTask/onAfterTask`、`instructions.getPageInstructions(url)`、`transformPageContent`。

**执行臂决策：选 CDP（jev-ultrafast 方式），page-agent 仅作 MFA/免安装降级臂**
一票否决级理由：①保真（合成事件 `isTrusted=false` 会让"测试通过而真实用户失败"）②隔离（page-agent 跑在用户当前标签页，无隔离语义）③导航（无 goto → 用例起点不可控）。
工程理由：④jev-ultrafast 有 `fresh()` 节点守卫 + `elementFromPoint` 遮挡检查，page-agent 只有弱索引检查；⑤jev-ultrafast 1 请求/步 + `recent_actions` 仅留 10 条，page-agent `<agent_history>` 全量累积 + 系统提示词 9,794 字节。

**★ CDP 复用现有浏览器状态：本机实测通过（14/14）**
条件：Chrome 153.0.8010.48 + Playwright 1.63.0，临时 user-data-dir（未碰真实 profile）。
- ✅ `connectOverCDP` 连通；✅ 既有 context 的 cookie/localStorage 可读（复用会话成立）
- ✅ **`browser.newContext()` 可用且 cookie 隔离为 0**（强隔离成立，纠正了"Playwright CDP 模式不支持 newContext"的猜测）
- ✅ 既有 `context.newPage()` 可用（弱隔离）
- ✅ 断言原语全通：`getByRole` / `getByLabel().inputValue()` / `isChecked()` / `screenshot({mask})`
- ✅ `Target.createTarget(background:true)` + `attachToTarget` + `closeTarget` 全通
- ✅ **`browser.close()` 不会关闭用户浏览器**（3/3 轮复核：端点存活、页面仍在）

**三条实测踩坑（会浪费半天，务必记住）**
1. **Chrome 111+ 必须加 `--remote-allow-origins=*`**。否则 WS 连上即被以 `code=1006` 断开，Playwright 只报 `Timeout 30000ms exceeded`，**错误信息完全不指向真实原因**。
2. **受限沙箱里 Chrome 自身 sandbox 起不来** → `sandbox initialization failed: Operation not permitted` → GPU 进程退出 → `FATAL: GPU process isn't usable. Goodbye.`。需 `--no-sandbox --disable-dev-shm-usage --disable-gpu-sandbox`（仅限 CI/容器）。
3. **连续测试复用同一调试端口会被残留进程污染**，`/json/version` 返回 404，看起来像"Playwright 连不上"。每次换端口。

**★ 方法论教训（重要）**：首轮实测曾误判为"Playwright 无法连接 Chrome 153"，根因实为沙箱拒绝 Chrome 自身沙箱。**凡"连不上"类结论，必须先用原生 WebSocket 直连 CDP 隔离出是哪一侧的问题**，再下判断。用 `--no-sandbox` 复核后 14/14 全通过，推翻原结论。

**Playwright 在 ESM 下不读 `NODE_PATH`**，脚本必须放进含 `node_modules` 的目录内运行。

## 追加：产品定义 + Skills 支撑边界（第三轮，承接「要产品化，核心功能与形态是什么」）

**交付物**：`20260922-jev-bs-e2e-research/final/product-definition.md`

**产品定位**：寄生在开发者现有浏览器里的 BS 系统回归测试工具 —— 用例进，证据级报告出。
差异化三角：①免搭建会话（复用已登录 Chrome、后台标签页不抢焦点、每 case 隔离）②判定不自证（只有确定性断言能产生 FAIL）③报告是证据（用例原文/遮罩截图/四列对照/可粘贴回放命令）。

**六个核心功能面**：用例即资产 / 接管浏览器 / 三级定位+学习飞轮 / 三态判定+问题三分类 / 证据级报告五要素 / 零模型回放。
横向预留：双执行臂（CDP 主干 + in-page 降级）。

**★ 形态判断（新增结论）**：不是"一个 CLI"，而是 **daemon + CLI + 本地控制台** 三件套 —— 类比 Docker 而非 Playwright。
判据：复用现有浏览器状态需要 CDP 长连接 + tab 池 + 会话账本，一次性进程做不到（每次要手动开带调试端口的 Chrome、无 tab 池、端口污染无法自愈）。
演进：**A 纯 CLI（MVP）→ B daemon+CLI+控制台（目标）→ C 平台化（仅预留接口，别提前做）**。
存储：文件式产物 + SQLite 索引，**不上 MySQL/PG**。

**★ Skills 支撑判定（核心结论，已固化进技能）**：
- 原则：**Skills 是给模型看的操作规程，不是给机器执行的运行时。**
- 能支撑**体验层 60–70%**，不能支撑**可信度 0%**。一句话：**Skills 决定好不好用，代码决定可不可信。**
- 可 skill 化（6 个）：`e2e-case-author`（PRD→.cases）、`e2e-run-and-triage`、`e2e-report-review`、`e2e-locator-heal`、`e2e-flake-triage`、`e2e-framework-audit`（已有）。
- 必须落代码：动作派发、断言求值、三态判定、截图取证、报告写盘、零模型回放。定位只允许 L3 兜底由模型做。
- 三条硬约束：①skill 只能经 CLI+JSON 交互 ②输出必须是"建议"不是"结论" ③每个 skill 必须声明降级命令。验收口径：**删掉全部 skill，CLI 依然完整可用**。
- 顺序铁律：**引擎 P1–P4 先行，skills 从 P4 起叠加**；先做 skills 只会得到"能演示、不能上生产"的聪明 demo。

**★ 学习飞轮（本产品最被低估的资产）**：L3 模型定位成功 → 控件指纹写回 `plan.json` → 下次同一条路走零成本的 L2。
结论：**模型成本随跑次数单调递减到零**。对照表述：agent 每次都重新犯错，runner 只错一次。产品化要求把"固化"做成显式动作（按钮 + 阈值 + diff 预览）。

**可衡量指标（已写入产品文档）**：同一 case 连跑 10 次结论一致率 100%；FAIL 人工复核为真缺陷 >80%；BLOCKED 占比 <15%；稳定期每 case 模型调用 ≤0.2；L1 命中率 >80%；单 case P50 <10s；clone→首个 PASS <30min。

**技能更新**：`ai-e2e-test-framework-audit` 增加「第七步：产品化时的 Skill 层/引擎层边界判定」（14 项能力判定表 + 三条硬约束 + 顺序铁律 + 形态判断），并扩充 frontmatter description 触发词。

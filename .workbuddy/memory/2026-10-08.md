### 六个必须记住的设计（可直接抄规格）

1. **三步骤骨架**：Goal(`agent.act`，模型管怎么做) / Assertion(`agent.assert`·`waitFor`·`extract`) / Locator(`screen`·`expect`，零模型)。＝我们「Playwright 管怎么做 / JEV 管选什么 / Evidence+Oracle 管对不对」的工程化形式。
2. **回放缓存**：`agent.act` 的动作**只在「后来的独立验证步骤」通过后才固化**。算验证＝定位器匹配器 / 引擎断言 / `locator.waitFor` / `agent.assert`·`waitFor`；**不算**＝裸值断言 / `poll` / 读取 / `extract` / 另一个 `act` / **「用例自己过了」**（掐死自证）。回放 4 步：核对起点屏幕 → 逐个找回控件重放（**歧义即停**）→ 核对终点（**必须有变化发生在本次回放首次屏幕之后**：「already on screen before the actions that should produce it proves nothing」）→ 无模型结束或带记录交回 agent。命名计数算效果、裸数字不算、导航后的屏幕上的计数不算（防上轮残留）。
3. **`--strict-cache` = `REPLAY_STALE`，不调模型不重试 exit 2**（理由：*a retry never replays and would pass live*）。**但默认是 hand-off（heal）** → 默认值与我们铁律 3 相反，需显式改。
4. **`@e2e-dev/decision`**：模型**只输出候选元素序号**（`MAX_CHOICES=255`，视口优先，超出计 `omitted`），动作绑定在代码里（`Target.run()`）；唯一候选不提问；`minProbability`/`minConfidence` 门限（**默认全关**）；**源码注释注明 prompt 规则改编自 `jev-ultrafast` 的 `NEXT_ACTION`/`TARGET`** → JEV 血统直接可见。明确缺口：无视觉、无 navigate、无拖拽/上传/悬停、无多选 listbox。
5. **Bug bash 的判定权归属**（★ 最值得抄）：编码 Agent 起 5–10 个 charter × 4 并发 `e2e explore` → 合并发现 → 剔除已知原因 → **为每条写复现测试** → **只有测试以 `ASSERTION_FAILED` 失败才算 bug**。Agent 只负责「怀疑」，确定性测试负责「定罪」。
6. **官方 benchmark 的度量方式**（★ 工程实践）：`apps/web-benchmark` 是 20+ 个硬场景（嵌套 shadow root / 纯 Canvas / 嵌套 iframe / 原生对话框 / 第二个标签页 / 拖放 / 每秒重挂载 DOM / 说谎的访问树）；`planted-bugs.e2e.ts` **断言的正是「对植入 bug 的正确行为做 `agent.assert` 应当失败」→ 在度量漏检，不是度量通过率**。做不到的场景**声明并 skip 写清原因**，让缺口每次运行都可见。

### 两处与 IDWTH 铁律冲突（必须回写判定层设计）

| 冲突 | 源码证据 | 处置 |
|---|---|---|
| **① `ASSERTION_INCONCLUSIVE` 归 `failed` 类，exit 1** —— 即「模型判不出来」被记为**测试失败**（文档原文 *A failure, never a pass*） | `packages/decision/src/executor.ts:382`：`/** Insufficient evidence must never become an assertion pass. */ function inconclusive(...) { return { status: 'failed', errorCode: 'ASSERTION_INCONCLUSIVE' } }`；错误码表 class=`test` | 它怕的是假 PASS，动机对但代价是假 FAIL。**我们保留自己的口径**：抄这个独立错误码，但把 class 改成 BLOCKED，不计入 bug 检出 |
| **② 默认 heal 不 verify** | `docs/cache.mdx` 原文承认 *"quiet by default: the agent takes the step over, the test passes, and every CI run pays for the model calls until someone re-records"* | IDWTH 的 `replay` **默认必须是 `--verify`**；`--heal` 显式开启且产物不入 CI |

### 其余对 IDWTH 有用的实测事实

- **判定器实现哈希它没有**（只绑 instruction/params/agent/agentContext/app identity/engine）→ 判定口径改了新旧 verdict 不可比，我们的绑定面是超集。
- **视觉噪声标定它没有**：`vision: true` 直接进模型判定，无 `ε_base`、无 `visual_unstable` 拒绝机制 → 我们铁律 13 是超集。
- **Canvas 有确定性路径**：官方 benchmark 用 `browser.evaluate` + `canvas.getContext('2d').getImageData` 读像素/数色带来断言 canvas 场景 —— 这是**不走模型视觉**的第三条路，比我们原方案多一个选项，值得写进 `visual-dom-matrix.md`。
- **iframe 支持（含嵌套）**：`browser.frameLocator` → 帧内 `screen` 查询。**藏在 `docs/browser.mdx:84`，不在 `web.mdx` 正文**，差点漏判「不支持」。
- **遮罩是输入控件级且 fail-closed**：`closed-shadow.ts:110` *"a mask that cannot prove its coverage must fail closed"*；`maskingProven` 校验。**但页面上渲染出的 kubeconfig/Bearer 是 `<div>`/`<pre>`，不在遮罩集里** → 与我们「两个易漏泄漏口」判断一致，仍需补文本级遮罩。密钥填入后**整轮禁止截图**（只覆盖 fill，不覆盖 app 自行渲染）。
- **无 origin 白名单**：导航与密钥填充都无 allowlist，Agent 可带本步声明的密钥跟到别站。
- **`command.log` 不脱敏**（app 的 stdout/stderr 原样落盘）；**视频不遮罩**标 `redaction:"incomplete"`。
- **CDP attach 有口子但不是给我们的**：`web({ connect: { cdpEndpoint } })` 定位为 hosted-browser（Kernel/EAS）接线，`browser` provider 与 `connect` 互斥；**无文档化的「接管我登录好的 Chrome」流程**。
- **Telemetry 默认开启**（每次 CLI 调用 → `eu.i.posthog.com`；声明不含测试/应用内容与凭据）→ 合规环境须 disable 并在 CI env 同步设置。
- **pre-1.0 会改 API，且升级会 re-key 全部缓存条目**（升级即重录）→ 必须锁版本，升级走独立 PR 并重录。

## 下午追加：以 `tester-army/e2e` 为基线的 IDWTH 架构调整方案

**用户问题**：「基于这个框架是否可以用于优化 PRD 配套的设计方案？架构应该如何调整」。

**产出**：`final/e2e-architecture-adjustment.md`（新建，236 行）；README 交付物表加一行。

**结论**：**可以，但「优化」必须限定为一个动作 —— 把它作为 IDWTH 的「执行与证据引擎」，插在判定内核之下。不是重画架构，也不是 fork。**
一句话判据：**用它的手上功夫，保住我们的判决权。**

**为什么是「可以」的三条硬依据**：
1. **同技术栈** —— IDWTH §11 目录结构全为 `.ts`（`runtime/executor.ts`、`tools/browser/*.ts`），e2e 是 TS + npm 包 → **这不是「借鉴设计」，是可写进 `package.json` 的真实依赖**（Apache-2.0）。四仓库里只有它满足这个物理前提。
2. 它成熟的那段 = IDWTH 里**工程量大但不含领域知识**的那段（§5.1 BrowserTool 七方法 + §5.5 十一个脚本 + §3.3 三级定位 + §9.4 遮罩 + §3.6 Trace）。
3. 它空白的那段 = IDWTH 的**核心资产**（runId 隔离 / 论域收窄 / 系统对象排除 / cleanup 终态 / `judge_impl_hash` / 判定离线重算）。

**FR 级映射（12 条）**：FR-6 Judge 与 FR-11 runId 隔离 **完全自研不动** · FR-1 契约编写保持自研（e2e 无「文档→用例」）· FR-2/3/5/7/8 **换底层** · FR-4/9/10 **包一层** · FR-12 判据自研。
→ **含判定语义的一条都没被替换，这是本次调整的安全边界。**

**架构调整（唯一一处）**：三层 → **四层**，在实现层与 Tool Layer 之间插入 **`EngineProvider` 接口层**。
- 与 IDWTH 已有的 `BackendAdapter`（§5.3）/ `JevDecisionProvider`（§7.1）**同一手法** —— 可替换性是既有设计语言，不是新增复杂度。
- 默认实现 = `@e2e-dev/web` + `-decision`；降级实现 = 自研 Playwright adapter。
- ⚠️ **`attach.ts`（CDP 接管）与 `background-tab.ts`（后台标签页不抢焦点）必须保持自研 —— e2e 不提供这两件**，它们是 E01/P0 实测出来的领域知识。

**七处必须显式改写的口径**（否则实现时被上游默认值带走）：① inconclusive→`failed` 改 BLOCKED ② replay 默认 verify ③ fixtures 绑 runId ④ 断言论域收窄 + 系统对象排除 ⑤ cleanup 终态判据 ⑥ 报告权威 schema 按五要素重写 + 配色重写（它产物是工程语言）⑦ **绑定项扩到七项**。

**★ 本次新发现 1：绑定面缺一个上游项。** 上游**升级即 re-key 全部缓存条目**，效果等价于我们的 `BLOCKED(drift)`，但它默认 heal **不报错** → 不把 `engine_provider_version` 绑进策略产物，「引擎换了但指纹还在复用」会成为新的**静默错配通道**。

**★ 本次新发现 2：A7「离线可跑」必须拆两条。** IDWTH 的 A7 原文「断开 JEV 端点 → 确定性路径全部可跑，SIR = 0」在 e2e 路径下**只在回放态成立**：
- **A7a 回放态**（缓存命中）断网 → ✅ 全部可跑，零模型。
- **A7b 首次态**（缓存未命中）断网 → 需 L3 / `agent.act` 的 step 必须 `BLOCKED(decision)`，**不得假装跑过**。
→ **由此产生一项交付物清单变更：内网/离线部署时「已录制的引擎缓存」必须随版本交付**（先在联网环境录一轮，缓存产物随包带入内网）。这是 IDWTH 原有交付物清单里没有的一项。

**新增验收 A10/A11**：A10（断言区在视口外 / 加载中 / 纯 Canvas 页面上做断言 → 必须 `BLOCKED(decision)` 而**不得报 FAIL**，守上游假 FAIL 通道）；A11（陈旧记录用**默认命令**回放 → 必须报错终止，**不得静默 heal 后报通过**）。

**明确建议「不做」**：**不要 fork**。理由：pre-1.0 改 API + 判定层的正确落点本来就是我们的 Runtime（改在它里面 = 把领域知识藏进一个会被升级覆盖的地方）+ Apache-2.0 允许直接依赖，包装比复制省。

**互补性证据（它缺、我们有）**：`origins_allowlist`（它无导航白名单）· 文本级遮罩（它只遮输入控件，遮不住渲染出的 kubeconfig/token）· `judge_impl_hash`（它无判定器哈希 → 新旧 verdict 不可比）。
→ **三者证明是互补而非替代**：它的强项是我们的工程量，我们的强项是它不打算做的判定与合规。

**待决 5 项（已写入文档 §11，需人拍板）**：① 默认实现走 e2e 还是先自研再逐步替换（建议**两条并行跑通做对照**，M3 用实测数据定默认值）② 是否把 `apps/web-benchmark` 硬场景集纳入我们的回归基准（建议**纳入**）③ 引擎缓存进不进版本交付物（建议**进**）④ 是否采用它的 `trace.md` 作证据呈现（建议**仅作可选渲染，不作权威产物**）⑤ 上游错误码要不要在报告露出（建议**露出但降级为附加字段 `upstream_error_code`**，避免非工程读者误读）。

**回写 `detailed-design.md` 的 9 处清单已列（文档 §10），未执行** —— 那是开发基线，等用户确认。

## 零、结论

| 问题 | 答案 |
|---|---|
| 能不能做 | **能，且有一条被实测证据支撑的唯一必要场景**（E01：ECharts 画在 Canvas 上，DOM 里没有数据） |
| 形式是什么 | **不是两条并列通道，是主从** —— DOM 负责"操作与判定"，视觉负责"看见 DOM 看不见的东西" |
| 视觉能不能产生 FAIL | **观察角色能（须过噪声闸门）；定位角色永远不能**。这条区分是整个设计的支点 |
| Skills 要不要从 7 个扩到 14 个 | **不要**。模态是每个 skill 内部的**参数**，不是新 skill。只新增 **2 个**（7 → 9） |
| 必须落代码的新增 | **3 个模块**，都是 Runtime 独占或强制点，**不能做成 skill** |
| 何时上 | **P4.5**（回放与 CI 打通之后）。理由见 §十 |

**一句话记住**：
> **DOM 的价值是"能证明唯一"，视觉的价值是"能看见渲染"。**
> 谁也不能替谁 —— 但**只有前者有资格宣判 FAIL**。

## 一、判定：为什么是主从，不是并列

三条实证，每条都指向同一个方向。

### 1.1 DOM 能证明唯一性，视觉不能

架构铁律 6 要求 **匹配数 > 1 即 BLOCKED，禁止取第一个**。这个规则的成立前提是"匹配数可计算"。

| 通道 | 唯一性判据 | 可否计算 |
|---|---|---|
| DOM | `matched == 1`（ARIA role/label/text 命中数） | ✅ 精确整数 |
| 视觉 | 「最像的那个」 | ❌ **只有排序，没有计数** |

视觉**无法表达"匹配数 > 1"这个状态** —— 它总会返回一个最像的候选，哪怕页面上有五个长得一样的按钮。
→ 所以视觉**不能承担 L1/L2**，只能做 L3 兜底。

### 1.2 视觉的延迟与成本高两个数量级

第三方横向实测（50 行 × 8 列表格页，视觉模型 Qwen3-VL-72B）：

| 操作 | Playwright (CSS) | Playwright (text) | 视觉方案 |
|---|---|---|---|
| 定位搜索框 | 12 ms | 8 ms | **950 ms** |
| 点击分页第 3 页 | 15 ms | 20 ms | **1100 ms** |
| 提取表格数据 | 3 ms | — | **3200 ms** |
| 每次运行成本 | $0 | $0 | **~$0.003** |

**慢约 50–100 倍。** 而本设计的单 case P50 耗时目标是 **< 10s**，若默认走视觉，一个 10 步 case 仅定位就 10s 以上，指标直接失守。

> ⚠️ **数据来源说明**：该组数字来自第三方对比文章（CSDN 实测博文 + 对比站转述），**非我方一手实测**。结论方向（视觉慢 1–2 个数量级、有 token 成本）与所有公开材料的定性描述一致，**但具体数值需在 P4.5 立项时用我们自己的目标系统复测**。已登记为待验证项 **H01**。

### 1.3 视觉定位的产出是坐标，**不可回放**

| 通道 | 定位产出 | 回放时 | 进 Frozen Strategy |
|---|---|---|---|
| DOM | `elementId`（代码拥有的整数）+ 指纹 | 逐步比对 `strategy` / `matched` → 可检测漂移 | ✅ |
| 视觉 | 坐标 / bounding box | **分辨率、DPR、滚动位置、响应式断点任一变化即失效** | ❌ |

**这直接破坏 P0 验收「回放全程零模型调用」** —— 视觉定位的步骤在回放时**必须重新调用模型**，那就不是回放。

### 1.4 但视觉有一条**不可替代**的必要性

E01 侦察已实测：**openFuyao 的 ECharts 全部画在 Canvas 上，DOM 里没有数据**（`ECharts 12 处命中`）。V1 的处置是**整块排除图表页**。

DOM 通道对 Canvas、WebGL、图片、跨域 iframe 的内容**结构性无能** —— 不是"selector 易碎"，是**根本不存在可寻址的 DOM 节点**。

所以正确的表述是：

> **视觉不是"更聪明的定位"，而是"另一种感知"。**
> 它在 DOM 无法感知的地方是**唯一手段**，在 DOM 能感知的地方是**纯负债**。

## 二、视觉的三类角色

| 角色 | 做什么 | 能否产生 FAIL | 形态 | 关键约束 |
|---|---|---|---|---|
| **V-A 观察者** | 渲染结果比对（Canvas / 布局 / 像素） | ✅ **能**（须过闸门） | **纯代码** | 见 §四 |
| **V-B 定位兜底** | DOM 不可达元素的目标解析 | ❌ **永不** | 代码 + JEV | 见 §三 |
| **V-C 取证** | 报告截图 | — | 纯代码 | 已有（F5），但遮罩升级见 §六 |

### 2.1 V-A 是唯一能让 Canvas 进入断言体系的确定性路径

**注意是"确定性视觉算法"，不是"VLM 判断"**：

| 方法 | 确定性 | 可产生 FAIL | 说明 |
|---|---|---|---|
| 像素比对 / SSIM | ✅ | ✅ | 阈值必须过噪声闸门（§四） |
| 结构化检测（区域内有 N 条折线、图例色块存在） | ✅ | ✅ | 需图像处理代码 |
| **VLM 描述（"图表看起来正常"）** | ❌ | **❌ 禁止** | 恒为 candidate，与 `issue.source = model` 同类 |

> **这一条是"判定不自证"原则的视觉版。** 它有一个很强的外部佐证：**视觉方案自己的官方文档就要求**「为降低模型假阳/假阴的风险，需要确定性校验时，应把 AI 查询与标准代码断言组合使用」。
> **厂商自己承认视觉断言不确定** —— 我们不应比厂商更激进。

**视觉通道的独立价值（必须能被验收证明）**：

| 场景 | backend/HTTP 断言 | 视觉断言 |
|---|---|---|
| 图表数据正确、**渲染错误**（轴线错位、序列颜色错） | ✅ PASS（数据没错） | **FAIL** ← 唯一能发现 |
| 数据正确、**图例被遮挡/截断** | ✅ PASS | **FAIL** |
| 数据正确、**字号溢出/重叠** | ✅ PASS | **FAIL** |

→ 对应验收项 **VB-01**（§十一）。

### 2.2 V-B 的产出必须立刻转译，否则不入冻结产物

视觉定位成功后的**强制动作**：
1. 先尝试**反查 DOM 锚点**（该坐标下的元素若可被 ARIA 解析 → 转成 `strategy: role/label`）→ 可入 Frozen Strategy
2. 反查不到（纯 Canvas 元素）→ 该 step 标 `replayable: false` → **CI Runtime 拒绝执行该 case**（§五）

**绝不把坐标写进 Frozen Strategy 当作主定位。** 那等于把"零模型回放"这条验收作废。

## 三、候选集约束：模型不能创造目标（**铁律 12**）

视觉接入 JEV 的关键，是**把"看图找元素"降维成"在代码给出的候选里选一个"**。

这是「**论域收窄**」的**第三次应用** —— 前两次分别是"残留致假 PASS"与"系统注入致假 FAIL"：

| # | 论域问题 | 收窄方式 |
|---|---|---|
| 1 | 上次运行的**残留**让 `exists` 恒真（假 PASS） | 论域收窄到「本 run 创建的对象集」 |
| 2 | 系统的**自动注入**让 `count == 0` 恒假（假 FAIL） | 同上 + `excluded_system_objects[]` |
| **3** | **模型的自由输出空间**让"页面上没有的东西"也能被点到 | **收窄到「代码生成的候选集」** |

### 3.1 必须这样做，不能那样做

| | 形式 | 后果 |
|---|---|---|
| ❌ | VLM 输出 `{x: 480, y: 320}` 直接点击 | 坐标可落在任何"看起来像按钮"的地方（包括图片、水印、广告位）→ **模型凭空创造目标** |
| ✅ | 代码先枚举候选并编号 → 模型只输出**候选集内的 index** | 候选集为空则 `unavailable` → **模型无法绕过「页面上没有这个东西」这个事实** |

这保持了既有设计的 `Unused target heads cannot cause an action` 性质：

```ts
// L3 的两种模态共用同一个出口，只是候选来源不同
type Candidate = {
  candidateId: number;      // ★ 由代码分配，绝不来自模型
  source: 'dom' | 'vision';
  bbox?: [number, number, number, number];   // vision 候选才有
  elementId?: number;       // dom 候选才有
  role: string; label: string;
};

// 模型输出：{ choice: 7 }  —— 只有 index，没有坐标、没有 selector、没有 JS
```

**校验层**（在 §7.3 合法性校验之后追加）：
1. `choice ∈ candidateIds` —— 不在集内 → `BLOCKED(decision)`
2. `candidateId → ElementHandle` 的反查必须由代码完成
3. 越界输出**必须有独立的审计事件**（不是静默丢弃）

### 3.2 视觉候选从哪来（顺序不可颠倒）

```
① DOM 可交互元素枚举      role/aria + 可点击 + 可聚焦          ← 永远第一步
② Canvas 区域分块         按 canvas 尺寸切网格 / 按已知图表结构分区
③ 可访问性树补充          DOM 枚举漏掉的自定义控件
        ↓ 合并、去重、编号
      候选集（可能为空）
        ↓
  空 → BLOCKED(decision)，不调模型
  非空 → 交给 JEV / 视觉模型选 index
```

**模型永远不参与候选生成。** 它只在最后一步做「在 N 个里挑一个」。

## 四、视觉 Oracle 的噪声闸门（**铁律 13**）

### 4.1 视觉断言自带一个新失败模式

| 通道 | 失败源 | 性质 |
|---|---|---|
| DOM | selector 失效、结构变更 | **可诊断**（报得出哪个 selector 没命中） |
| 视觉 | **渲染噪声**：字体抗锯齿、GPU 光栅化差异、DPR、动画中间帧、实时图表刷新 | **不可诊断**（只有"像素差 3.7%"） |

若直接设一个经验阈值（如 0.1%）→ **必然 flaky** → 重演「误报率失控」→ 团队三周后忽略报告。

### 4.2 强制前置：噪声下界标定

这是架构铁律 7「**稳定性指标不能取平均**」的视觉版 —— 在给视觉断言定阈值之前，**先测出这台机器上的噪声地板**。

| 步 | 动作 | 判据 |
|---|---|---|
| 1 | 同环境同页面同断点，**连拍 N ≥ 10 次**（页面静止、动画关闭、字体已加载） | 得到 N 张同源截图 |
| 2 | 逐像素差异统计 | 得噪声下界 `ε_base`（取 p95） |
| 3 | 断言阈值必须 **`> k · ε_base`**（k ≥ 3） | 不满足 → 该区域标 `visual_unstable` → **拒绝生成视觉断言** |
| 4 | 区域含**动画 / 实时刷新 / 时间戳 / 光标闪烁** | 直接判 `visual_unstable`，不进标定 |

**`visual_unstable` 的区域不生成断言，也不降级为 candidate —— 而是明确报"此处不可测"。** 这与「复杂度不足即 BLOCKED，不得退化为 FAIL」同源。

### 4.3 Runtime 独占项从 4 个扩为 5 个（⚠️ 随视觉通道归入 Backlog，V1 仍为 4 项）

| # | 独占项 | 为什么必须独占 |
|---|---|---|
| ①–④ | Judge 调用权 · verdict 写入权 · Freshness 校验权 · cleanup 执行权 | 已有（§6.1） |
| **⑤** | **噪声闸门校验权** | 若允许 step 自带阈值，则"标定"可被绕过 → 阈值退化回经验值 → flaky 回归。**必须由 Runtime 在加载 Contract 时校验 `threshold > k · ε_base`** |

且 `noise_gate.env_fingerprint_hash` 必须与当前 `env_fingerprint` 匹配 —— **换机器/换浏览器版本后标定失效，必须重新标定**，否则"在我机器上过了"会成为新的假 PASS 通道。

> ⚠️ **约束必须在代码里**：*"a prompt instruction alone is not enforcement"*。写在 Contract 注释里或 SKILL.md 里的一句话**不算**强制。

## 五、回放的内禀缺陷与 `replayable` 声明

视觉通道有一个**必须显式建模、不能假装没有**的缺陷：**纯 Canvas 目标不可回放**。

| 场景 | `run`（Authoring，允许模型） | `replay --verify`（CI，零模型） |
|---|---|---|
| step 全部 `replayable: true` | ✅ 执行 | ✅ 执行，逐步比对漂移 |
| step 含 `replayable: false` | ✅ 执行（该步走视觉） | **❌ 报 `BLOCKED(unreplayable)` 并终止** |

**为什么是"终止"而不是"跳过"**：
- 静默跳过 → 该 case 在 CI 里**少了断言还报绿灯** → 假 PASS 的新通道
- 与铁律 3 一致：**禁止静默适配状态漂移**；不可回放也是一种漂移

**代价是诚实的**：宁可报"这条 case 上不了 CI，请人工在发布前跑一次"，也不要让它带着不可回放步骤混进门禁。

> 这条也给出了**视觉覆盖率的上限**：**`replayable: false` 的 step 占比就是"这个 case 不能进 CI 的比例"**，可直接作为产品指标。

## 六、遮罩升级：截图从「证据」变成「输入」

这是视觉通道引入的**唯一新增泄漏面**，且它比看起来严重。

| | 引入视觉前 | 引入视觉后 |
|---|---|---|
| 截图去向 | 只进报告，**人看** | **同时进模型上下文**（第三方 API） |
| 泄漏范围 | 本地文件（D13 已登记） | **本地文件 + 模型供应商** |

D13 已指出：`input, textarea, [contenteditable], [data-private]` 这套遮罩集**遮不住页面上渲染的凭据明文**（kubeconfig 片段、Bearer token —— 它们不是输入框）。
E01 又实测出该平台**密码以字节数组提交、凭据可能以明文渲染**。

所以送模型前必须做**确定性敏感区域排除**：

```
① 代码定位敏感节点（含凭据的 DOM 节点 / 已知密钥模式匹配的文本节点）
② 取其 boundingBox
③ 在该 bbox 内做涂抹（纯色覆盖），再截图送模型
④ 涂抹记录进 Trace（涂抹了哪几块，不进 judgement_set）
```

**不能靠"提示词让模型别看"。** 又是一次 `a prompt instruction alone is not enforcement`。
→ 落成模块 **`SensitiveRegionMasker`**（§7.4），验收项 **VB-05**。

## 七、Skills 矩阵

### 7.1 为什么不是 14 个 skill

最自然的想法是给每个视觉能力新建一个 skill（视觉契约、视觉执行、视觉动作、视觉恢复、视觉证据、视觉判定、视觉回放…）。**这是错的**，两个理由：

1. **既有 7 个 skill 的切分轴是"能力面"（契约/执行/动作/恢复/证据/判定/回放），不是"模态"。** 模态是每个能力面的**参数**。按模态重切会得到 7 × 2 = 14 个横切重复的 skill，职责边界立刻模糊。
2. **违反"反对版本膨胀"** —— 且真正需要人机交互的视觉能力其实只有 2 个（基线审批、差异分诊），其余都是代码。

### 7.2 矩阵（主交付物）

**7 个骨架不变，模态横向切入；新增 2 个（视觉专有的"人机接口"性质能力）。**

| Skill | 模态 | 阶段 | 能否产生 FAIL | 形态 | 视觉引入了什么变化 |
|---|---|---|---|---|---|
| `web-test-contract` | DOM + 视觉声明 | Authoring | ❌ | SKILL.md | 新增 `kind: visual` 断言与 `modality: vision` 步骤 |
| **`web-visual-baseline`** 🆕 | 视觉 | Authoring + 人审 | ❌ | SKILL.md + CLI | **全新**：基线的建立/审批/淘汰 |
| `web-test-executor` | DOM + 视觉 | Runtime | ❌（执行层） | **代码** | 加载 Candidates 生成、`replayable` 门禁 |
| `web-semantic-action` | 🔵 `dom \| vision` | Runtime / L3 | ❌ **永不** | 代码 + JEV | 候选集合并、index 校验（铁律 12） |
| `web-semantic-recovery` | DOM | Runtime | ❌ | 代码 + JEV | 不变（visual recovery 无意义：已失败的动作不该靠看图重试） |
| `web-test-evidence` | DOM + 截图 | Runtime | ❌ | **代码** | 遮罩升级为敏感区域排除 |
| `web-test-judge` | 🔵 `dom \| visual \| backend \| http` | Runtime 判定 | ✅ **能** | **代码**（Runtime 独占） | 新增 visual oracle 求值 + 噪声闸门校验（独占⑤） |
| `web-test-replay` | DOM + 视觉 | Runtime 回放 | ❌ | **代码** | 遇 `replayable: false` → 报错终止 |
| **`web-visual-diff-triage`** 🆕 | 视觉 | 事后诊断 | ❌（只加分诊） | SKILL.md | **全新**：区分真缺陷 vs 渲染噪声 vs 基线过期 |

图例：🔵 = 模态作为参数横向切入（**不是新 skill**）。

**两个新增 skill 的共性**：它们都是**需要人做判断/审批**的环节，这正是 skill 的适用域（§4.1 控制面）。其余视觉能力全是代码。

### 7.3 新增 skill 规格

**`web-visual-baseline`** —— 视觉基线管理

| 项 | 内容 |
|---|---|
| 触发 | "批准这个基线 / 基线要怎么定 / 基线过期了" |
| 输入 | runId + 待审批截图 |
| 输出 | 基线版本（`artifact://baselines/<name>@v<N>.png`）+ 变更说明 + 审批记录 |
| 硬约束 | ① **不自动批准**（必须人确认）② 记录 `approved_by` / `approved_at` / `env_fingerprint_hash` ③ **换环境必须重新建立基线**，不允许跨环境复用 |
| 降级路径 | 人手动把截图放进 `baselines/` + `idwth baseline approve <name>` |
| 为什么是 skill | 这是**审批流**，不是计算；需要写给人看的变更说明 |

**`web-visual-diff-triage`** —— 视觉差异分诊

| 项 | 内容 |
|---|---|
| 触发 | 视觉断言 FAIL，但不确定是真缺陷还是噪声 |
| 输入 | runId + 基线图 + 实测图 + 差异图 + `ε_base` |
| 输出 | 分诊结论（真缺陷 / 渲染噪声 / 基线过期 / 环境漂移）+ 证据 + 建议动作 |
| 硬约束 | ① **不得改写 verdict** ② 建议"更新基线"时必须**显式列出被忽略的差异块**，禁止一键静默更新 |
| 降级路径 | 人肉对比 `diff.png` + 换环境重跑一次看是否复现 |
| 为什么是 skill | 需要跨证据推理与归因，且产出是**给人看的建议** |

### 7.4 必须落代码的 3 个模块（**不能做成 skill**）

| 模块 | 职责 | 为什么不能 skill |
|---|---|---|
| **`VisualOracle`** | 像素/SSIM/结构化比对；阈值求值 | **判定逻辑** —— 调用权与写入权必须归 Runtime（铁律 2） |
| **`VisualStabilityCalibrator`** | 连拍 N 次、测 `ε_base`、判定 `visual_unstable` | **前置闸门** —— 必须由 Runtime 在加载 Contract 时强制，不可由 step 自愿（独占⑤） |
| **`SensitiveRegionMasker`** | 定位敏感节点 → bbox → 涂抹 → 再送模型 | **安全边界** —— 靠提示词不算强制 |

三个都落在 `runtime/`，与既有 `resolveTarget()` / `evaluateAssertion()` / `judge()` 同级。

## 八、成本账：为什么视觉不做默认通道

| 维度 | DOM | 视觉 |
|---|---|---|
| 单步延迟 | 毫秒级 | 秒级（慢 50–100×） |
| 单次成本 | $0 | 有 token 成本（约 500–2000 tokens/步） |
| 唯一性可证 | ✅ | ❌ |
| 可回放 | ✅ | 部分（须转译，否则 `replayable: false`） |
| 抗 UI 重构 | 弱（selector 易碎） | 强（相对存活率 23% → 89%） |
| **Canvas / 渲染层** | **❌ 无能** | ✅ **唯一手段** |
| 视口外元素 | ✅ 可定位 | ❌ **只能看到 viewport 内** |

**最后一行是反向的硬约束**：视觉方案官方文档明确承认「截图只能看到 viewport 内的内容，元素不在视口则无法定位」。**DOM 能定位视口外元素（自动滚动），视觉不能。** 这是又一个"两者强项不重叠"的证明。

**关键取舍**：视觉最被宣传的优势是**抗 UI 重构**。但在本架构里，抗重构由 **L2 指纹复用 + 学习飞轮**解决，**成本为零且可回放**。

> 所以：**不要把视觉用在"DOM 能做但 selector 易碎"的地方** —— 那是飞轮的活。
> **只用在"DOM 根本做不到"的地方** —— 那才是视觉不可替代的领域。

## 九、Contract 扩展

### 9.1 视觉断言

```yaml
assertions:
  - kind: visual
    id: "chart-rendered"
    region:
      anchor: "div.chart-container"        # ★ 必须由 DOM 锚点定界
      # 禁止出现绝对坐标 (x, y, w, h) —— 分辨率/DPR 变化即失效
    compare:
      method: ssim                          # pixel_diff | ssim | structural
      baseline: artifact://baselines/chart-main@v3.png
      threshold: 0.02                       # ★ 必须 > k · epsilon_base
    noise_gate:
      epsilon_base: 0.0031                  # 标定所得噪声下界
      k: 3
      calibrated_at: "2026-09-23T19:00:00+08:00"
      env_fingerprint_hash: "sha256:..."
    on_unstable: reject                     # reject | blocked
```

**三条校验规则（由 `idwth validate` 强制）**：
1. `region.anchor` 必填；**出现绝对坐标即校验失败**
2. `threshold > k · noise_gate.epsilon_base`；否则拒绝加载
3. `env_fingerprint_hash` 必须与当前运行环境匹配；不匹配 → `BLOCKED(env)` 并要求重新标定

### 9.2 视觉步骤

```yaml
steps:
  - intent: "在图例中选中 CPU 使用率序列"
    target: "CPU 使用率图例项"
    modality: vision          # dom（默认） | vision
    replayable: false         # ★ 显式声明；缺失时默认 true（保守）
    risk: reversible
```

**CI Runtime 行为分级**：

| 命令 | 遇 `replayable: false` |
|---|---|
| `idwth run` | 允许执行（走视觉 L3 + 候选集校验） |
| `idwth replay --verify` | **报 `BLOCKED(unreplayable)` 并终止**（不静默跳过） |
| `idwth replay --heal` | 允许，产物标 `not_for_ci` |

## 十、路线图位置：P4.5（⚠️ 2026-10-10：该时点已撤销 —— 视觉通道转入 Backlog，条件触发）

| 阶段 | 视觉通道状态 | 理由 |
|---|---|---|
| P1–P3 | **完全不引入** | MVP 硬标准是"同一 case 连跑 10 次结论一致"。视觉的渲染噪声直接威胁这条 —— **先证明 DOM 路径稳定，再引入变量** |
| **P4.5** | **引入，且必须先过闸门** | 回放与 CI 已打通 → 有稳定的漂移检测与退出码契约可依赖；此时视觉的噪声问题可被 `replay --verify` 立刻暴露 |
| P5+ | 常规能力 | 常驻 harness 阶段做基线库与趋势 ⚠️ **2026-10-10：常驻 harness 未采纳（V1 = 纯 CLI，见 `detailed-design.md` DD-47）；本行为 Backlog 设想，非规划** |

**进入 P4.5 的三个前置条件（全部满足才立项）**：
1. **DOM 路径的稳定性闸门已通过**（无 flaky case）
2. **噪声标定器已实现并跑通**（`VisualStabilityCalibrator`）
3. **有真实 Canvas 断言需求**（openFuyao 的 ECharts 图表页就是现成的）

**加载条件**：**当且仅当** Contract 声明了 `kind: visual` 或 `modality: vision` 时，视觉通道才被加载。**默认关闭**，与 `allow_multiple` 同构。

## 十一、新增验收项 VB-01–VB-05（原 A10–A14 · 2026-10-10 改号：避开执行引擎层 A10/A11 撞号）

| # | 验收 | 通过判据 | 证伪什么 |
|---|---|---|---|
| **VB-01** | **视觉通道的独立价值** | 构造"Canvas 图表**数据正确但渲染错误**（如轴线错位）"：`backend` 断言 **PASS**，`visual` 断言 **FAIL** → 证明视觉不是重复劳动 | 若两者结论总是一致 → 视觉无独立价值，应删除 |
| **VB-02** | **噪声闸门有效性** | 同环境静止页面连拍 10 次：全部 `pixel_diff < k · ε_base` → 不满足则对应区域必须被标 `visual_unstable` 且**拒绝生成断言** | 若标定后仍 flaky → 阈值模型不成立 |
| **VB-03** | **模型不能创造目标** | 构造 prompt 注入 / 畸形响应，令模型返回**候选集外的 index** → 必须 `BLOCKED(decision)`，**零动作派发**，并留审计事件 | 若越界仍可派发 → 铁律 12 未落地 |
| **VB-04** | **不可回放必须显式失败** | 含 `replayable: false` 的 case 执行 `replay --verify` → 必须报 `BLOCKED(unreplayable)` 并终止；**不得静默跳过、不得报 PASS** | 若静默跳过 → 假 PASS 新通道 |
| **VB-05** | **敏感区域排除** | 页面渲染明文 Bearer token，触发视觉路径：**grep 送模型的请求体** → 必须不含该明文 | 若含 → 泄漏面成立，视觉通道不得启用 |

## 十二、一页速查

| 问题 | 答案 |
|---|---|
| 能不能做 | 能。**唯一硬需求**：Canvas/WebGL（E01 实测：ECharts 画在 Canvas，DOM 无数据） |
| 什么形式 | **主从**：DOM 管操作与判定，视觉管渲染层观察 |
| 视觉能否产生 FAIL | **观察角色能（须过噪声闸门）；定位角色永不** |
| 视觉能否进 L1/L2 | **不能** —— 无法表达"匹配数 > 1"，无法满足铁律 6 |
| 能否进 CI 回放 | 仅当能转译为 DOM 锚点；否则 `replayable: false` → **拒绝执行** |
| 视觉接 JEV 的关键 | **候选集由代码生成并编号，模型只输出 index**（铁律 12） |
| 视觉断言的关键 | **先标定噪声下界 `ε_base`，阈值必须 > 3·ε_base**（铁律 13） |
| Skills 变化 | 7 → **9**（新增 `web-visual-baseline`、`web-visual-diff-triage`）；模态是参数不是 skill —— **归 Backlog，V1 仍为 7** |
| 必须落代码 | **3 个模块**：`VisualOracle` / `VisualStabilityCalibrator` / `SensitiveRegionMasker` |
| Runtime 独占 | 4 → **5**（新增**噪声闸门校验权**）—— **归 Backlog，V1 仍为 4** |
| 何时上 | ~~P4.5~~ → **Backlog（条件触发）**，且必须先过 DOM 路径的稳定性闸门 |
| 最容易被误用 | 拿视觉去解决"selector 易碎" —— 那是**学习飞轮**的活，且飞轮零成本 |

**新增铁律**
- **11** —— 视觉不能证明唯一性，因此**永不进入 L1/L2、永不产生 FAIL**（除非作为观察者的确定性算法）
- **12** —— **模型不能创造目标**：候选集由代码生成并编号，模型只在集内选 index，越界即 `BLOCKED(decision)`
- **13** —— **视觉断言的阈值必须先标定噪声下界**（连拍 N≥10 取 p95），未标定或 `visual_unstable` 的区域**拒绝生成视觉断言**
